# What to do during B.Tech?

|      |                     |
|------|---------------------|
| Programming | Low level to high-level, single system to distributed system, procedural & declarative |
| Cross compilation | Learn to compile code for non-native CPU architectures (MCUs, ARM etc.) |
| MCUs | Learn flashing, clocks, I/O, data transfer protocols etc. Learn to read reference manuals. |
| Sensors | Try varieties of sensors, with various interfaces to MCUs. Learn to read datasheets.  |
| Design circuits | Start from bread-board and move to vero-board (soldering). Learn circuit design |
| MPUs | Try [Raspberry pi](https://www.raspberrypi.com/), [Beagleboard](https://www.beagleboard.org/boards) etc, with custom Linux OSs |
| Network and Comm. | Start with bluetooth, zigbee and RF. Move to ethernet and virtual networks. |

# How to become an industry relevant Engineer?

|      |                     |
|------|---------------------|
| Read job descriptions from leading industries across the globe (not just India) on linkedin <br> --> That will give you ideas on what skills and competencies you should acquire for the real world. <br> --> It is a continuous process as the variety is huge and dynamic. Start early - do not wait till final year. |
| Read research areas (not just products) of leading industries on their respective websites <br> --> That will provide you insights on what to learn and focus on next. <br> --> What problems are the best of industries trying to solve next. <br> --> E.g.: [Google Research](https://research.google/research-areas/), [Microsoft Research](https://www.microsoft.com/en-us/research/), [Nvidia Research](https://www.nvidia.com/en-us/research/), [IBM Research](https://research.ibm.com/) etc. |
| Demonstrate industry relevant skills <br> --> Create Open Source Projects. Bonus if you have other contributors. <br> --> Contribute to any Open Source Project. Bonus if that OSS is well-known. |

# High Level Direction


|      |                     |
|------|---------------------|
| Learn by doing | Try to experiment with everything, be stupidly brave to build and experiment <br> E.g.: Try pattern recognition using Eigen vectors. |
| Be cross disciplinary | Any good project spans over multiple domains, beyond engineering. <br> E.g.: [AlphaFold](https://deepmind.google/technologies/alphafold/) is revolutionizing medical sciences |
| Programming is paramount | Learn to write code. Learn to read code. <br> Even HW design is code (both electronics & mechanical). <br> Use simulators. If desired simulator does not exist, create it! |
| Be curious | Learn working principles of things around us. |
| R&D drives the world | Be educated and updated with latest research. <br> Develop perspective on what is expected from the world in next 5 to 10 years |

# FAQ

> AI can program. Do I need to learn programming?
  * Yes! Just because calculators can add, should we not learn addition any more?
  * AI is going to assist you in programming; it will make you faster and efficient.
  * But we may still need to tell AI what to do and how to do it!
    * In fact we may have to read and understand more programs, as we will have to verify if programs from AI are solving the intended task in desired way.

<br><br>

> Which programming language(s) should I learn?
  * A single project usually uses several languages
  * Every language has its target space: Use the one that fits the task.
  * The more variety of languages you can use, the more advanced you can be with your projects.


---

# FAQ (page 2)

> I have studied C programming. How do I know if I know enough to be useful in industry?
  * Try to develop a small but useful Software, maybe for personal use. See if you know enough.
  * Beyond syntax there are few more things that are highly important to learn:
    * Build systems for Compiled languages (E.g.: [make](https://www.gnu.org/software/make/), [cmake](https://cmake.org/), [bazel](https://bazel.build/) for C and C++)
    * Version control ([git](https://git-scm.com/)) and repository hosting ([github](https://github.com/), [gitlab](https://about.gitlab.com/), [bitbucket](https://bitbucket.org/product/))
    * Deployment - distributable binary/installer or host on network/internet

<br>

> What should a developer machine look like?
  * Use linux as your primary / everyday OS. [Ubuntu](https://ubuntu.com/desktop) & [Fedora](https://fedoraproject.org/) are great options.
    * If you have a windows machine, make it dual boot. WSL might be limiting.
  * Learn to use containers. e.g.: [docker](https://docs.docker.com/) & [podman](https://podman.io/); and virtual machines / emulators: e.g.: [qemu](https://www.qemu.org/)
  * Learn to use [telnet](https://en.wikipedia.org/wiki/Telnet), [SSH](https://en.wikipedia.org/wiki/Secure_Shell) and [GPG](https://gnupg.org/).
  * Be comfortable with terminal and vi / vim editors. For IDE: [VScode](https://code.visualstudio.com/) would be a good choice.
